# Arquitetura do Legis (Editor de Atos Normativos)

Este documento descreve a arquitetura técnica do módulo `legis`, focado na edição, estruturação e consolidação de atos normativos. O sistema garante consistência total entre a edição (WYSIWYG) e a visualização (Consolidada/Situações Especiais).

## 1. Visão Geral

O `legis` permite a criação e edição de textos normativos (Leis, Decretos) com suporte a:
-   **Estruturação Automática**: Detecção de Artigos, Parágrafos, Incisos.
-   **Situações Especiais**: Veto, Nova Redação, Revogação, etc.
-   **Visualização Consolidada**: Renderização do texto com as alterações aplicadas.

## 2. Gerenciamento de Estado

O estado é gerenciado centralmente no componente `PageForm`, sincronizando dados estruturados com o editor visual (Tiptap).

### Componentes Principais

-   **`PageForm.tsx`**: O orquestrador principal.
    -   Mantém o estado `structuredElements` (`NormativeElement[]`).
    -   Gerencia o editor Tiptap (`LegisEditor`).
    -   Sincroniza atualizações do painel lateral (`SpecialSituationsPanel`) para o editor.
    -   **Responsabilidade Chave**: Garantir que alterações nos metadados (ex: adicionar um Veto) sejam propagadas para o nó correspondente no documento do editor via transações Tiptap (`setNodeMarkup`).

-   **`LegisEditor.tsx` / `NovelEditorWrapper`**: O editor visual.
    -   Baseado em **Tiptap** e **Novel**.
    -   Utiliza a extensão `NormativeAttributes` (`extensions.ts`) para renderizar estilos visuais baseados nos metadados do nó.
    -   Utiliza a extensão `ReferenceExtension` (`reference-node.tsx`) para renderizar vínculos com outras normas.

-   **`SpecialSituationsPanel.tsx`**: Painel lateral de propriedades.
    -   Interface para adicionar/remover `SpecialSituation`.
    -   Emite eventos `onUpdate` que são capturados pelo `PageForm`.

-   **`SituationCard.tsx`**: Componente de visualização (UI).
    -   Renderiza os "modais" ou cartões de situações no texto consolidado.
    -   Consome a lógica de agrupamento de `SituationLogic.ts`.

## 3. Estruturas de Dados (`domain/entities.ts`)

### `NormativeElementEntity`
A unidade atômica do texto (ex: um Artigo).
```typescript
interface NormativeElementEntity {
  id: string;
  type: ElementType; // 'Artigo', 'Parágrafo', etc.
  index: string;     // '1º', 'I', etc.
  text: string;      // Conteúdo HTML
  specialSituations: SpecialSituation[]; // Lista de alterações
  originalStartValidity: Validity;
  // ...
}
```

### `SpecialSituation`
Representa uma alteração ou evento legal.
```typescript
interface SpecialSituation {
  type: SituationType; // 'Veto', 'Nova redação', 'Revogação', etc.
  date: string;
  dispositivo?: string; // Texto de referência (ex: "Art. 23")
  newText?: string;     // Novo texto (para Nova Redação)
  vetoText?: string;    // Texto vetado
  // ...
}
```

## 4. Regras de Negócio e Comportamento

A lógica de negócio é isolada em arquivos de serviço/lógica para garantir testabilidade e consistência.

### 4.1. Lógica de Visualização e Estilo (`SituationLogic.ts`)

Responsável por interpretar a lista de `specialSituations` de um elemento para fins de visualização (Cards) e estilo.

-   **Agrupamento (`groupSituationsForElement`)**: Agrupa situações por proximidade semântica para exibição nos cards laterais.
    -   `VETO_GROUP`: Veto, Derrubada de veto.
    -   `ALTERATION_GROUP`: Nova redação, Renumeração, Alteração de ementa.
    -   `VIGOR_GROUP`: Suspensão, Restauração, Perda de eficácia.
    -   `EXISTENCE_GROUP`: Revogação, Anulação, Cassação, Acréscimo, Repristinação.
    -   `VALIDITY_GROUP`: Alterações de vigência.
    -   `INTERPRETATION_GROUP`: Interpretações constitucionais.

-   **Ordenação**: Cronológica (mais recente primeiro) dentro dos grupos e entre os grupos.

-   **Estilização (`getElementStyle` & `extensions.ts`)**: Define como o texto deve aparecer no Editor e na Visualização.
    -   **Azul (`text-blue-700`)**: Texto novo em vigor (Nova redação, Acréscimo, Alteração de ementa).
    -   **Laranja (`text-orange-600`)**: Texto em disputa ou restaurado (Derrubada de veto, Repristinação, Restauração).
    -   **Tachado (`line-through`)**: Texto inativo (Veto mantido, Revogação, Suspensão, Anulação).
    -   **Vermelho (`text-red-600`)**: Vigência futura (ainda não em vigor).
    -   **Sublinhado (`underline`)**: Interpretação/Declaração.

### 4.2. Lógica de Consolidação (`ConsolidationLogic.ts`)

Responsável por gerar a "Visão Consolidada" (Texto final limpo).

-   **`isElementInactive(element)`**: Determina se o elemento deve ser oculto/substituído por separador.
    -   Retorna `true` se: Veto (sem derrubada), Revogação (sem repristinação), Anulação, Cassação.
    -   Retorna `false` se: Ativo, Nova Redação, ou se a situação negativa foi revertida (ex: Veto derrubado).

-   **`processElementsForConsolidated(elements)`**: Filtra a lista de elementos, substituindo sequências de inativos por separadores (`[...]`).

## 5. Auto-Estruturação e Chaves

O sistema possui um mecanismo inteligente para transformar texto plano em estrutura normativa (`NormativeElement[]`).

### 5.1. Motor de Regras (`rules-engine.ts`)
Utiliza expressões regulares (Regex) para identificar padrões de texto.
-   **Exemplos de Regras:**
    -   `^Art\. (\d+)` -> Tipo: `Artigo`, Índice: `X`.
    -   `^§ (\d+)` -> Tipo: `Parágrafo`, Índice: `X`.
    -   `^[IVX]+` -> Tipo: `Inciso`.
-   **Detecção de Revogação/Veto no Texto**: O motor também detecta se o texto está tachado (`<s>`, `<strike>`) ou contém `(REVOGADO)`/`(VETADO)` e cria automaticamente uma situação especial correspondente.

### 5.2. Sincronização e Proteção de Dados (`PageForm.tsx`)
A função `performSync` converte os blocos do editor Tiptap em elementos estruturados.

-   **Preservação de Dados (Não Sobrescrever)**:
    -   O editor armazena o `normativeId` de cada elemento nos atributos do nó (`attrs.normativeId`).
    -   Ao sincronizar, o sistema busca o elemento existente pelo ID.
    -   Se o ID existe, o sistema preserva todos os metadados (`specialSituations`, `validity`, etc.) e atualiza apenas o conteúdo textual (`text`).
    -   Isso impede que uma re-estruturação acidental apague dados históricos inseridos via painel lateral.

### 5.3. Geração de Chaves (`display-logic.ts`)
A função `getElementKey` gera a representação textual canônica do índice do elemento (ex: transforma `type: 'Artigo', index: '1'` em `"Art. 1º "`). Isso é usado na visualização para garantir consistência tipográfica.

### 5.4. Vínculos e Referências (`reference-node.tsx`)
O sistema permite inserir referências dinâmicas a outros atos normativos dentro do texto (ex: Coletâneas).

-   **Componente**: `ReferenceExtension` (Tiptap Node) e `ReferenceComponent` (React View).
-   **Funcionalidade**:
    -   Renderiza um bloco interativo dentro do editor.
    -   Pode referenciar um documento inteiro ou **trechos específicos** (Artigos selecionados).
    -   **Smart Segments**: Suporta a seleção de segmentos de texto, permitindo ocultar partes irrelevantes (substituídas por `[...]`) para focar apenas no conteúdo relevante da referência.
    -   **Live Updates**: O componente busca os dados mais recentes do documento referenciado via `pageService`, garantindo que o texto da referência esteja sempre atualizado.
    -   **Estilo Consistente**: Reutiliza `ElementContent` para garantir que o texto referenciado siga as mesmas regras de estilo (tachado, azul, etc.) que o documento principal.
